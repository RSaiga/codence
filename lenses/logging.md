# logging — ログの観点

変更を下の項目と、ログの一覧（`profile.md` の `lenses.logging.catalog`。無くてよい）に照らして読む。
障害のときログから原因までたどれない箇所と、ログが穴になる箇所を指摘する。監査の記録は見ない。
ログの口は `lenses.logging.logger`（無ければコードから探す）。口が自動で付ける項目を、変更に求めない。

| 番号 | 項目 | 疑うところ |
|---|---|---|
| LOG-1 | 原因を捨てる | 記録や投げ直しで、元の例外（メッセージ・スタック・`cause`）を捨てる |
| LOG-2 | 手がかりの欠け | 失敗の記録に、誰の・どの操作か・対象の ID が無い |
| LOG-3 | 出してはいけないもの | パスワード、トークン、鍵、カード番号、個人情報。本文・ヘッダー・設定を丸ごと（CWE-532） |
| LOG-4 | 偽装できる行 | 外からの値を、改行を消さずに文字列のログへ埋め込む（CWE-117）。構造化した項目なら当たらない |
| LOG-5 | 残すかの問い | 一覧の出来事か、お金・契約の操作の結果、外部のサービスの失敗、ジョブの始まりと終わり、設定の変更、起動と停止に、ログが無い。要求ごとの行と包みの記録で足りるものは除く |

- LOG-1〜4 は指摘。「高」には、障害のときログから何がたどれないか（何が漏れるか、どう偽装できるか）を書く。
- LOG-5 は問い。足せと言わず、残さないと何がたどれないかと「残すか。残さないなら理由を一覧に」を聞く。一覧に「残さない」とある出来事は聞かない。
- レベル・言い回し・量の好みは指摘しない。

```
### [LOG-<番号> <項目>] — <file>:<line>  (確信度: 高/中/低)
- 何が問題か / 障害のとき（高は必須）/ 提案する手当て
### [LOG-5 残すかの問い] — <file>:<line>  (問い)
- 出来事 / 残さないと / 聞くこと
```
最後の行は `## LENS CLEAN` か `## LENS FINDINGS <件数>`（問いも数える）。
